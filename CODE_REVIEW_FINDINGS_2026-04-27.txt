MULTI-VENDOR HUAWEI VRP — ENGINEERING CODE REVIEW
===============================================

Reviewer: Network Engineering perspective
Scope: All files created/modified in Phases 1A-2B
Date: 2026-04-27

OVERALL ASSESSMENT
------------------
The architecture is solid. The VendorProfile ABC + SessionConfig pattern is clean, the dependency direction is correct (everything imports FROM vendors, never the reverse), and the default-fallback-everywhere strategy genuinely protects existing Cisco functionality. The code is well-organized and the separation of concerns is good.

However, I found 8 critical bugs, 13 medium issues, and 4 low-priority improvements that need attention before this goes to production or a demo.


CRITICAL BUGS
-------------

C1: Huawei OSPF redistribution into RIP — wrong "import-route rip 1"
File: huawei_vrp.py
The _redist_into_ospf method returns "import-route rip 1". On Huawei VRP, the default RIP process doesn't require an instance number. The correct redistribution command is simply "import-route rip".

C2: Huawei RIP redistribution — "metric" is not valid VRP syntax
File: huawei_vrp.py
Returns "import-route ospf 1 metric 3". On Huawei VRP, the correct keyword is "cost", not "metric". The device will reject this command.

C3: SSH sender sends save command twice
File: sender.py
The "save" command is sent as part of the normal block loop, then sent AGAIN explicitly. This triggers a second Y/N confirmation prompt on Huawei, causing latency and timing risks.

C4: Telnet sender — missing save confirmation handling
File: sender.py
The telnet async sender never calls the save confirmation handler. When "save" is sent on Huawei, the device prompts Y/N but the response Y is never sent. Config will not be saved.

C5: Huawei prompt regex matches [Y/N] as a device prompt
File: huawei_vrp.py
Regex [<>\]]\\s*$ matches "Are you sure to continue?[Y/N]". The code falsely thinks it found a prompt and stops before sending the Y response.

C6: Stale "interface range" command in Huawei VLAN block
File: huawei_vrp.py
Huawei VRP doesn't have an "interface range" command. This line is dead code from Cisco logic and will produce an error.

C7: GNS3 detection keyword "ar" will false-positive on Cisco devices
File: huawei_vrp.py
The keyword "ar" is too short and appears in many Cisco image names (e.g., "adventerprise"). This would misdetect Cisco devices as Huawei.

C8: Wizard summary preview shows Cisco, templates save Huawei
File: guided_setup_wizard.py
The preview panel uses old hardcoded Cisco render methods, but the save flow uses the new ConfigEngine. The user sees wrong commands in the UI before deploying.
